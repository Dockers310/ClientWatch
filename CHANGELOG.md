# Changelog ClientWatch

Общая история изменений. Новые версии сверху.

## 2.2.11

### Исправления
- Исправлена ошибка компиляции в `WatchRegistry`: обновление отображаемого названия теперь вызывается через `Entry.title(...)`, а не через неизменяемый `SearchResult` record.
- Сохранены исправления меню, статусов, `Shift+ПКМ` и взаимодействия с ClientWatch Companion из 2.2.10.

## 2.2.10

### Смена статуса из меню игрока
- `Shift+ПКМ` по любому обнаруженному моду теперь действительно меняет его статус.
- Если мод ещё не добавлен через «Запрошенные моды», первый `Shift+ПКМ` автоматически создаёт локальное правило со статусом `Запрещён`.
- Следующие `Shift+ПКМ` переключают статусы по кругу: `Запрещён → Требует проверки → Разрешён → Старая разрешённая версия → Запрещён`.
- В меню игрока вместо сообщения «не добавлен — менять статус нечего» теперь показывается действие добавления.
- Для локальных правил отключено принудительное превращение `Разрешён` в `Требует проверки`: правило применяется ко всем версиям обнаруженного мода.

### Названия
- Если после старого сохранения в `watchlist.yml` в качестве названия оказался технический ключ вида `modrinth:XeEZ3fK2`, ClientWatch при совпадении с реально обнаруженным модом восстанавливает нормальное имя из профиля игрока и сохраняет его.

## 2.2.9

### GUI
- Добавлено `Shift+ПКМ` по моду в профиле игрока для смены статуса записи в «Запрошенных модах».
- В подсказке предмета явно показано текущее сочетание для смены статуса.
- Исправлена обработка `Shift+ПКМ` в списке «Запрошенных модов»: сначала проверяется точный `SHIFT_RIGHT`, чтобы он не воспринимался как обычный ПКМ.
- Асинхронный поиск/загрузка больше не переоткрывает старое меню поверх другого GUI и не перехватывает последующие клики.

### ClientWatch Companion
- Запрос списка модов повторяется до 3 раз с одним и тем же nonce.
- В консоль добавлена запись об отправке запроса и предупреждение, если Companion не ответил после всех попыток.
- Сохраняется проверка nonce — старые/чужие ответы не принимаются.

### Сохранение названий
- Старые записи `watchlist.yml`, у которых вместо названия сохранился ключ вида `modrinth:...` или `curseforge:...`, при загрузке пытаются восстановить читаемое имя из исходного запроса/slug и сохраняются с исправленным названием.

### Диагностика
- Для обмена с Fabric Companion сервер по-прежнему использует обычный Paper/Bukkit plugin channel.

## 2.2.8

### Цвета модов
- Меню модов игрока классифицирует не только `cw:` записи Companion, но и старые записи `fp:`/`ch:`.
- Незапрошенные моды больше не показываются лаймовым красителем только потому, что присутствуют в последнем заходе.
- Мод, полученный несколькими источниками (`cw:`, `fp:`, `ch:`), объединяется в одну запись; приоритет у Companion.
- Краситель берётся строго из `WatchStatus`: красный / жёлтый / лаймовый / серый. Незапрошенные — фиолетовые.

### Игрок с Companion
- В заголовке меню модов ник игрока отображается золотым и жирным, если Companion уже прислал отчёт.
- В меню «Игроки» сохранено золотое жирное выделение ника и добавлена единая классификация модов.

### Клики GUI
- Обычные левые клики используют `ClickType.isLeftClick()`, чтобы не терять корректные варианты клиентских кликов.
- Обычные правые клики для смены статуса используют `ClickType.isRightClick()`.

## 2.2.7

### Цвета модов
- Статус из «Запрошенных модов» определяется только по совпавшему проекту, а не по глобальному SHA-сопоставлению.
- Неизвестные Companion-моды больше не считаются автоматически разрешёнными — в меню игрока они фиолетовые.
- Запрещённый — красный, требующий проверки — жёлтый, разрешённый — лаймовый, старая разрешённая версия — серый.
- Улучшено сопоставление Fabric ID, slug, project-id и названия проекта.

### Меню игроков
- Цвета модов в списке игрока используют ту же классификацию, что и меню модов игрока.
- Добавлена понятная легенда цветов.

### Прочее
- Сохранено исправление `SchedulerUtil` и защита от ошибки `Could not pass event InventoryClickEvent`.

## 2.2.6

- Исправлена окраска предметов в меню модов игрока: статус из «Запрошенных модов» имеет приоритет и применяется к любому источнику обнаружения.
- Список игроков: наличие ClientWatch Companion заметно по `[CW]`, отдельной строке и свечению предмета.
- В карточке файла подписано, где SHA-512, где SHA-1 и где CurseForge fingerprint.
- При добавлении мода явно указано, что он попадает в раздел «Запрошенные моды».
- Усилена обработка кликов GUI: верхний инвентарь определяется через `rawSlot`, обновление меню после действий откладывается на 1 тик (меньше пропусков ЛКМ/ПКМ).
- Исправлено падение `WatchRegistry.prefer()` при первом совпадении проекта: первый аргумент `null` обрабатывался как кандидат и вызывал `a.status()`. Из-за этого могло не открываться меню модов, а клики выглядели пропущенными (`Could not pass event InventoryClickEvent to ClientWatch v2.2.5`).
- Исправлено описание проверки: если совпал именно SHA-1, GUI больше не называет его SHA-512.
- Исправление сборки: добавлен отсутствовавший импорт `dev.antifreecam.util.SchedulerUtil` в `ModsGui.java` (`cannot find symbol: variable SchedulerUtil`).

- Режим «все версии проекта»: например, Freecam можно сразу сделать запрещённым для любой версии, даже если конкретный файл 26.2 ещё не найден в каталоге.

## 2.2.1

- Основная команда: `/afc`; старые алиасы сохранены.
- Клиентский мод полностью пассивный: без команд, меню, клавиш и настроек; только отвечает на запрос сервера.
- Просмотр полного списка модов — только у пользователей с доступом к плагину.
- Технические хэши описаны понятным русским языком: показывается проверочный код файла и объясняется, совпадает ли он с опубликованным оригиналом.
- Статус «требует проверки» используется при несовпадении проверочного кода у похожего мода.
- Неизвестные/неподтверждённые моды отображаются фиолетовым.
- Легаси-версии отображаются серым и имеют отдельное понятное название.
- Обновление списка проверяемых модов переклассифицирует уже полученные отчёты без перезахода.
- Обычная проверка для игроков без клиентского мода остаётся прежней.
- Старые данные сервера не переносятся и не удаляются; новый список хранится отдельно.

## 2.1.5

Собрано поверх предыдущих правок (ускоренная проверка при входе, отдельный доступ `pumpkin`, короткая команда `/afc p`) — все сохранены без изменений.

### Больше модов в базе (`mods-db.yml`)
Добавлены в базу известных модов (не читы и не срабатывания — только профиль игрока, как Sodium/JEI):
- Accurate Block Placement (Reborn)
- Gamma Utils
- Inventory Profiles Next
- Shield Status (walksy)
- Auto Clicker (pro.mikey / ErrorMikey)
- Simple AutoClicker (sansrus)
- AutoSwap (Nikrecs)
- XPlus Autofish

Для **ShieldFixes** и **Combat Hitboxes** надёжного способа определения не нашлось (в jar нет lang-файлов и клавиш) — комментарий прямо над этим местом в `mods-db.yml`.

Часть добавленных модов (автокликеры, автозаброс удочки, автосвап) даёт игровое преимущество, но по умолчанию они только в профиле, без уведомления персонала. Чтобы мод подсвечивался красным как читерский и слал алерт стаффу — перенести его в `config.yml` → `mods:` с `category: "cheat"`.

### Лаунчер и версия игры в профиле
Профиль игрока (`/afc mods <ник>`, список игроков, история заходов, список срабатываний Freecam) показывает:
- **Похоже на:** лаунчер/клиент, угаданный по client brand (Lunar Client, Badlion, Feather/Dawn, LabyMod, Polar, Hyperium, Vivecraft, известные читерские клиенты и т.д. — см. `dev/antifreecam/util/LauncherUtil.java`). Не гарантия: client brand присылает сам клиент и его можно подделать.
- **Версия игры:** определяется по протоколу подключения через PacketEvents (`ClientVersion` из хендшейка) — надёжнее, штатными средствами клиента не подделывается.

Оба поля сохраняются в `profiles.yml` и попадают в историю каждого захода.

## 2.0.1

### Paper + Folia
- Добавлена метка `folia-supported: true`.
- `api-version` обновлён до `26.2`.
- Убраны использования legacy `BukkitScheduler`.
- Добавлен `SchedulerUtil` на базе `EntityScheduler`, `GlobalRegionScheduler` и `AsyncScheduler`.
- Проверки игроков, таймер тыквы, перепроверка всех и отложенные GUI-действия — Folia-safe.
- Сетевые ответы PacketEvents передаются обратно в регион соответствующего игрока.
- Общие коллекции профилей, доступов, флагов и тыкв сделаны потокобезопасными.
- Сохранение `profiles.yml`, `flags.yml`, `access.yml` и `pumpkin.yml` не выполняется блокирующим I/O в регионе.
- Перезагрузка конфига выполняется через Global Region.

### Исправления после первой сборки
- Исправлен вызов `SchedulerUtil.onEntityLater(...)` в `DetectionManager` с лишним аргументом.
- Восстановлены импорты `org.bukkit.Bukkit` во всех GUI-классах, использующих `Bukkit.createInventory(...)` и `Bukkit.getOfflinePlayer(...)`.

### Проверка игроков и прогресс
- В карточку игрока добавлена кнопка **«Перепроверить игрока»** — полная перепроверка только этого онлайн-игрока.
- Перепроверка корректно отменяет незавершённую старую сессию и запускает новую, не оставляя старые таймеры.
- Исправлено зависание прогресса растянутой проверки: тайм-аут одной пачки повторяет ту же сессию, а не создаёт новую (меню могло навсегда показывать `1/N`).
- Прогресс считается по реально полученным ответам клиента.
- Открытая карточка игрока автоматически обновляет прогресс и по завершении обновляет полный список модов.

### Дополнительно
- Автоматическая проверка при входе ускорена: `join-spread-seconds: 10`, тайм-аут ответа 2 секунды, 1 повтор.
- Отдельный сохраняемый доступ `pumpkin` в `access.yml`.
- `Shift+ПКМ` в меню «Доступ» переключает доступ к тыкве, `Shift+ЛКМ` снимает именно этот доступ.
- Игрок только с доступом `pumpkin` может использовать `/afc pumpkin` без доступа ко всему меню ClientWatch.
- Короткая форма `/afc pumpkin on <ник>` и `/afc pumpkin off <ник>` используется в подсказках.
